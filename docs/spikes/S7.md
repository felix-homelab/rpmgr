# S7: Does the PKI behave as designed?

Status: Done · Date: 2026-10-06 · Issue: #11 · Code: tag `spike/s7` (branch `tmp/s7-pki` while
running)

## Question and rule

From [13](../13-roadmap.md#phase-0--spikes): issue and renew 7-day leaf certificates with new keys;
URI and DNS name constraints enforced by Go's verifier; per-identity DNS SANs with `ServerName` set
per peer; `VerifyConnection` runs on resumed TLS sessions and rejects a revoked identity; a `Reauth`
endpoint that accepts certificates expired within the grace period and nothing older, and refuses
superseded serials; a CSR bound to the TLS session via exported keying material. Pass: all checks
pass; revocation effective on resumed sessions. Decides
[ADR-0008](../adr/0008-internal-ca-mtls-spiffe.md).

Rules, agreed before the run: name constraints not enforced → rely on the `VerifyConnection` checks
only. `VerifyConnection` not run on resumed sessions → TLS resumption disabled for internal
sessions. CSR binding works → mandatory for `Enroll`, `Renew` and `Reauth`; otherwise not used.

Findings the design now uses ([F] in Go 1.27.1 source):

- `VerifyConnection` runs on resumed TLS 1.3 connections, client
  [F Go 1.27.1 `crypto/tls/handshake_client_tls13.go:595-604`] and server
  [F Go 1.27.1 `crypto/tls/handshake_server_tls13.go:1033-1042`, `:821-823`].
  `VerifyPeerCertificate` does not, including across configurations returned by `GetConfigForClient`
  [F Go 1.27.1 `crypto/tls/common.go:675-678`]: rpmgr puts every check into `VerifyConnection`.
- Resumption re-checks expiry and the stored chain: the server refuses a ticket whose client
  certificate expired [F Go 1.27.1 `crypto/tls/handshake_server_tls13.go:362-381`], the client one
  whose server certificate expired or no longer matches `ServerName`
  [F Go 1.27.1 `crypto/tls/handshake_client.go:405-429`]. A ticket never outlives its certificate.
- A configuration returned by `GetConfigForClient` (a `Clone`) shares the ticket keys: with tickets
  on, a ticket from `controller.<td>` resumed at `reauth.controller.<td>` (mutation 3). The Reauth
  configuration therefore sets `SessionTicketsDisabled`, which stops both resumption and new tickets
  [F Go 1.27.1 `crypto/tls/handshake_server_tls13.go:295-297,941-944`].
- URI name constraints are matched like DNS names against the URI host
  [F Go 1.27.1 `crypto/x509/constraints.go:525`], with a label boundary
  [F Go 1.27.1 `crypto/x509/constraints.go:223-250`]; an empty or IP host cannot be matched and is
  refused [F Go 1.27.1 `crypto/x509/constraints.go:582-607`]. The constraint `<td>` also admits
  `spiffe://x.<td>/…`, so `VerifyConnection` requires the host to equal `<td>` exactly.
- DNS SANs with `_` and upper-case letters are valid [F Go 1.27.1 `crypto/x509/parser.go:1411-1415`]
  and match `ServerName` case-insensitively.
- The Go TLS client still refuses to handshake without `ServerName`
  [F Go 1.27.1 `crypto/tls/handshake_client.go:47`].
- Exported keying material is unavailable when `Renegotiation` is set, even on TLS 1.3
  [F Go 1.27.1 `crypto/tls/conn.go:1643-1649`]; rpmgr's constructors never set it.
- The binding value is RFC 9266's `tls-exporter` (label `EXPORTER-Channel-Binding`, empty context,
  32 bytes), placed in a CSR extension; RFC 7030, Section 3.5, binds EST requests the same way. The
  spike used an OID under the documentation enterprise number 32473 (RFC 5612).

## Outcome

All checks pass, so the rules keep the design. [ADR-0008](../adr/0008-internal-ca-mtls-spiffe.md)
is **Accepted**:

- name constraints are enforced by Go and stay on the intermediate; `VerifyConnection` still checks
  the trust domain exactly;
- `VerifyConnection` runs on resumed sessions, so TLS resumption stays allowed for internal
  sessions;
- CSR binding works, so it is **mandatory** for `Enroll`, `Renew` and `Reauth`.

Changed in the same PR: ADR-0008, [04](../04-security.md) (identities, CA hierarchy, leaf
certificates, enrollment),
[03](../03-connections.md#properties-common-to-all-rpmgr-internal-sessions) and
[12](../12-testing-and-quality.md#security-testing) (four new regression tests), 13 (VB-17) and 14.

## Not verified

- Hardware-backed keys (TPM, PKCS#11) and the root kept offline: not part of S7.
- Intermediate rotation with overlap and root rotation by cross-signing: designed in 04, not run.
- The binding through ConnectRPC handlers: shown with `net/http` over HTTP/2 (`r.TLS`), which
  ConnectRPC runs on; reaching `r.TLS` from a ConnectRPC handler needs an HTTP middleware (S4).
- Other verifiers' handling of the URI name constraint (OpenSSL, browsers): rpmgr's peers are all
  Go; the constraint is defence in depth for them.
